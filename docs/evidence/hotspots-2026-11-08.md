# History and first-sync performance evidence

The acceptance dataset is the same immutable snapshot used in the preceding investigation:
commit `f42d36ee792c74d06afb4d098a91838cea95b1b1`, with 3,135 events, 397 issues, 16 journal
segments and 234 accepted-attempt files. Its journal is approximately 5.16 MB. No journal
payload or issue text is included in this evidence directory.

The baseline executable was built before edits from source commit
`33a6de608f64aebe68bfd16167a8a9849bd482cb`. Both executables use the same pinned Rust 1.99
toolchain and release profile on Linux x86-64. Binary hashes identify the tested artifacts;
the candidate was built from the working tree before its commit. This is local Linux evidence,
not macOS or hosted CI evidence.

## Reproduce

Keep the two release executables separately. Supply a local bare mirror containing the pinned
snapshot, without checking out or running bead in the real tracker:

```sh
python3 infra/hotspots.py \
  --before /tmp/bead-before --after target/release/bead \
  --snapshot /tmp/journal-snapshot.git \
  --ref f42d36ee792c74d06afb4d098a91838cea95b1b1 \
  --output /tmp/hotspots.json
```

The harness reads the source mirror into a private temporary mirror with a hook rejecting
every push. Every bead command has its own scratch `BEAD_HOME` and an explicit local remote;
`GIT_ALLOW_PROTOCOL=file` excludes network remotes. It never writes the source tracker.
Before/after order is interleaved with a fixed seed. Wall times include process startup and
captured output; OS caches are not flushed. Thirty samples cover each warm command and the
first limited history read without its metadata cache, with the state projection already warm.
Ten new homes per binary measure first sync, including the full-history local fetch.
The local mirror deliberately excludes GitHub network latency.

Every measured output is checked against the baseline SHA-256. Each fresh sync must report
zero pushed events and no integrity problems, then produce identical full-history and export
bytes. Sixty-four full-history reads with sixteen concurrent readers also start without the
history cache and must match. The temporary mirror ref must remain at the pinned commit.

## Measurements

The [raw report](hotspots-2026-11-08.json) contains every sample, output checksum, binary hash,
dataset shape and host load. The development host was shared with other work. The benchmark
ran after its own build and test processes finished; these results are not universal latency
bounds, particularly for fsync and network operations.

| Operation | Samples per binary | Before median | After median | Before p95 | After p95 |
|---|---:|---:|---:|---:|---:|
| Warm `log --limit 1 --json` | 30 | 42.40 ms | 17.46 ms | 45.23 ms | 18.68 ms |
| Warm default `log --json` | 30 | 42.25 ms | 17.78 ms | 48.11 ms | 19.37 ms |
| Warm full `log --limit 0 --json` | 30 | 61.90 ms | 35.82 ms | 67.00 ms | 40.19 ms |
| First limited log without history cache | 30 | 42.38 ms | 49.21 ms | 45.35 ms | 56.08 ms |
| First sync from local mirror | 10 | 4,222.70 ms | 1,080.63 ms | 4,313.29 ms | 1,121.32 ms |
| Warm `ready --json` control | 30 | 11.63 ms | 11.24 ms | 14.58 ms | 11.83 ms |
| Warm `export` control | 30 | 40.08 ms | 41.17 ms | 44.23 ms | 54.34 ms |

Limited warm history is **2.43 times faster** (59% less elapsed time); first sync is **3.91
times faster** (74% less elapsed time) in this run. Building the history cache costs about
6.8 ms extra on the first limited read. Every measured command's output matched its baseline
hash; every fresh copy produced identical exports and full history. All 64 concurrent history
reads matched, with the cache absent at their start. No sync pushed events, no integrity issue
was reported, and the temporary mirror ref stayed unchanged.

## Mechanism and tradeoffs

Warm history validates the build, every source file's settled identity and the checksum of
compact causal display metadata. It resolves current issue keys and machine aliases afterwards.
No operation payload enters the cache. A journal change invalidates it completely, and its
first read must still parse and order the entire journal before writing the cache. Hits decode
all metadata, so `--limit 1` is not constant-time in event count.

Initial download prepares and fsyncs at most eight independent files concurrently, then
installs them in listing order. A batch stops after eight files or four MiB of payload; a
single file may exceed that byte budget. Each worker is joined and every installed journal
file has completed its flush. Existing stores and pending attempts use the ordinary merge.
The parallel path also requires distinct absent targets, unaliased parent directories and
canonical machine names. Pre-existing filesystem aliases, duplicate paths and noncanonical
names retain serial merging; the empty events directory created by the store lock is allowed.

Independent syscall probes (`strace -f -c -e trace=fsync` before, and
`strace -f -ttt -y -e trace=fsync,rename` after) counted **255 fsync calls before and after**.
The candidate trace observed 250 download workers calling fsync across the batches, plus
two other threads/processes; these were not 250 simultaneous workers. A warm
`log --limit 1 --json` traced with `strace -f -e trace=openat` opened
**250 journal files before and zero after**. These traces establish the removed work and
retained flushes; their timings are not benchmark samples.
The [syscall and memory report](hotspots-2026-11-08-syscalls.json) records those observations
with the same executable hashes as the timing report.

The new history cache occupies 545,992 bytes on this snapshot. Single `/usr/bin/time` samples
of warm limited history used 15,220 KiB resident before and 9,740 KiB after; full history used
21,516 KiB and 15,716 KiB. These are individual observations, not statistical memory bounds.

## Verification

The unmodified baseline passed 1,247 tests and 14 infrastructure tests before implementation.
The final candidate passed `./check.sh --stress`: 1,257 baseline tests, with 11 intentionally
skipped, 14 infrastructure tests, and both six-machine stress models (2,400 reference-model
operations and 3,000 concurrent commands with partitions). The baseline took 128 seconds and
the stress models 220 seconds. Doctests completed with zero tests. Formatting and strict
workspace Clippy passed, as did focused bootstrap and destination-alias tests.
Coverage includes append, replacement, rotation,
removal, late causal attempts, excluded pending attempts, damaged and foreign caches,
unsettled timestamps, limits, filters and fresh aliases. Cache writes killed before or after
rename recover. Initial downloads killed before or after installation at files 1, 8, 9 and the
last file, and an injected ENOSPC, retry to identical journal bytes and exports.

The exact lint commands were `cargo fmt --all -- --check` and
`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings -D clippy::mod_module_files`.
The [verification record](hotspots-2026-11-08-verification.json) pins the final changed Rust
source hashes and tested executable. Measurements preceded the commit and PR; the candidate
was not installed and no live tracker mutation was performed. Concurrent work advanced the live
tracker during this implementation; the acceptance dataset remained the original immutable
snapshot throughout.

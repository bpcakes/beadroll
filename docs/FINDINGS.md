# Findings ledger

Every finding from every review, in one place. The reports themselves are kept verbatim under
`reviews/`; this file is the living record of what each finding became. A finding is **fixed**
when the behaviour is changed and a test fails without the fix; **optimized** when the behaviour
is kept byte for byte and only the work it takes is removed, so that the tests pass on both
implementations and a release probe is the evidence; **by design** when the behaviour is kept on
purpose (with the reason); **open** otherwise.

The Tests column names Rust tests: the crate whose tests hold them, then each test's path in its
test binary (`cargo nextest run -E 'test(/^PATH/)'` runs it, or a class's module of them). Each
finding until the cutover was tested in the Python suite, at `python-0.1.0`; every one of those
tests was ported to Rust, and at the cutover the inventory that mapped each to its port
(`cargo xtask inventory`) rewrote this column with their paths.

Rows that cite `RUST-PORT.md` by section (the U rows, reviews 8 and 9, and some others) cite the
plan the port followed, removed once the port was done (roll-dih8.24); it is in git:
`git show 5a6ea8d:docs/RUST-PORT.md`.

Reviewers: propose new rows in your report using the next free id for your review (see
`REVIEWING.md`); the maintainer merges them here.

## Decisions reviewers questioned and that stand

Recorded so they are not re-reported; see `REVIEWING.md` §2 for the full list.

- Claims never expire and there is no heartbeat; a missing owner needs a human `takeover`.
- The display value for a conflicted field is the newest event; there is no resolution command.
- An owner's `close` is a local write published at once, not a conditional update.
- No persisted projection; every command replays the journal.
- One ref, serialised publishing; claims take seconds under heavy contention.

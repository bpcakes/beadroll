# bp POC: third independent review

Reviewed 6 October 2026. The current revision fixes the exact executable cases behind several earlier findings, and all 142 shipped tests pass, but it does not close all 13 safety families. My final classification is **5 fixed and 8 partly fixed**. The most important remaining normal-operation failure is that recovery can recognize an accepted ownership attempt and then rebuild the operation anyway. That can report an accepted release as `NOT_OWNER`, duplicate a bundled update, and overwrite a causally later edit. Accepted multi-file ownership attempts also become locally visible one file at a time.

The six-machine models and the broad compatibility runs were healthy. Those successes do not contradict the focused failures: the traffic models do not inject lost acknowledgements or interrupt local confirmation, and ordinary comment IDs do not normally hit the deterministic collision fixtures.

## Ranked findings: normal operation and fault recovery

### N01 — High: an accepted ownership attempt is rebuilt after recovery

`coordinated()` fetches and merges on every retry. If `Link.merge()` finds the attempt on the remote, it confirms and removes the pending files. `settle_pending()` then reports clear, and `coordinated()` calls the command's `build()` function again instead of returning the result of the accepted attempt ([bp](bp:1553), especially lines 1567–1604).

Independently reproduced consequences:

- **Actual subprocess/transport fault:** a local bare remote's real `pre-receive` sleeps past `BP_NET_TIMEOUT=0.1` and then accepts the release. Both machines show the issue released, the pending directory is empty, but the command returns `NOT_OWNER` because it tries to release the already released claim again.
- **Actual crash hook and new process:** `BP_TEST_CRASH_AFTER_PUSH=1` exits after the remote accepts a release. Retrying `release` confirms the accepted event and then returns `NOT_OWNER`.
- **Injected transport result, real Git state:** after a real successful push, the harness changes only the returned client status to simulate a lost acknowledgement. A recovered `update --claim --title ...` emits `set` and `label_add` twice. If an intervening local title edit has already observed the first accepted update, the rebuilt update overwrites that causally later edit.

The last case separates an injected result from an actual subprocess timeout; it is not described as a second real transport fault. The actual timeout and crash/retry cases independently establish the incorrect command outcome. Relevant regressions are `ActualTransportReview`, `Protocol3.test_release_recovers_a_successful_push_with_lost_acknowledgement`, and `Protocol3.test_recovered_atomic_update_is_not_applied_again_after_a_later_observed_edit` in [test_review3.py](test_review3.py).

The original R01 rollback/journal-fork mechanism is gone: pending files plus a same-head fence prevent the delayed push from landing after a successful fence, and that actual receive-pack test passes. This is nevertheless a remaining failure of accepted-operation recovery, so R01 is only partly fixed.

### N02 — High for coherent local observation: accepted bundled attempts are confirmed file by file

`update --claim` publishes its claim, field edits, and label edits in one remote commit, but `confirm_ownership()` installs the detached files one at a time ([bp](bp:1039)). `Link.merge()` uses the same per-file path when importing an accepted pending attempt ([bp](bp:1383)). Readers do not share the writer lock.

Two independent schedules fail:

- Pausing after confirmation of the first file lets a real local `show` see the confirmed claim with the old title and without the bundled label. A peer sees the complete accepted transaction.
- Killing the command with actual `SIGKILL` after that first file leaves the partial state—claim visible, old title, no label—until a later `sync` imports the remaining accepted files.

The remote transaction remains intact and ordinary recovery converges, so this is not remote data loss. It violates the documented all-or-none attempt guarantee for local readers and makes a transient window durable across a process crash. See `Protocol3.test_reader_sees_all_or_none_of_accepted_claim_and_bundled_edits` and `test_kill_during_local_confirmation_does_not_leave_partial_atomic_update`.

## Ranked finding: performance on valid data

### P01 — High scalability risk: detached ownership ancestry is quadratic

The accepted absence of a persisted projection is not this finding. The new representation stores a cumulative `frozenset` of detached ancestors for every event ([bp](bp:625), [bp](bp:739)). A valid alternating claim/release history therefore retains about `n²/2` ancestor memberships.

Fresh safe-size reruns on the reviewed source:

|---:|---:|---:|---:|---:|
| 1,000 | 998 | 497,503 | 51,904,512 B | 0.0125 s |
| 3,000 | 2,998 | 4,492,503 | 249,217,024 B | 0.0917 s |
| 3,000 sequenced journal control | 0 | 0 | 35,127,296 B | 0.0162 s |

The supplied current-hash 10,000-event run, inspected but deliberately not repeated, recorded 49,975,003 memberships and 2,438,266,880 B peak RSS; the sequenced control recorded 50,495,488 B. These are synthetic in-memory replays, not thousands of real pushes. I stopped at 3,000 in the independent rerun because the supplied 10,000-event evidence already demonstrated excessive allocation. ## Ranked findings: malformed or hostile input robustness

These fixtures construct raw events. Normal commands did not emit them.

### C01 — Medium: an identical misplaced duplicate can reorder its real journal

The exact R05 malformed-variant order test now passes, but another duplicate boundary does not. If an identical event is encountered first in another machine's journal, placement uses that earliest raw copy. Combined with a broken real owner chain, delivery order changes the projection, drops a legitimate event, and invents a chain break. `State.seq` is also constructed from `journal.order` before `causal_order()` necessarily settles the journal ([bp](bp:517), [bp](bp:625)). Two permutations of the same raw event multiset produce different titles, conflicts, and integrity state.

Reproductions: both `test_identical_misplaced_duplicate...` methods in `test_review3`.

### C02 — Medium: quarantined dependency variants can still crash replay

The R07 intersection rule fixes the supplied descendant-cycle case, but two nearby cases escape its boundary:

- A quarantined variant with scalar `deps=17` raises `TypeError` while `effective_deps()` iterates it ([bp](bp:582)).
- Variants that agree on a descendant dependency can make `causal_order()` force-release the quarantine placeholder, after which replay looks up a dependency that has not populated `st.seen` and raises `KeyError` ([bp](bp:594), [bp](bp:739)).

These are uncaught tracker-wide failures, not scoped integrity entries. Reproductions include deterministic cycle and common-descendant variants in `ReplayThirdReview` and `ReplayResiduals`.

### C03 — Medium: incomplete create identity and embedded comments pass validation

Create validation explicitly accepts `issue=None` ([bp](bp:438)). Two such creates overwrite `st.issues[None]`; both exported keys become unresolvable and no integrity finding is recorded. This does not undo the exact R02 fix, which correctly rejects a create that names a different existing UID.

Embedded create comments are checked only for an object and string-like `text`. A comment with no UID/legacy ID and missing export fields reaches state ([bp](bp:823)); detail/export then raises `KeyError` at [bp](bp:1317). This is a remaining nested-validation boundary of R08.

### C04 — Medium: a same-issue takeover need not causally observe the claim it supersedes

The exact R06 wrong-issue orphan is fixed by checking issue identity, but the superseded pre-pass does not require `st.saw(takeover, previous claim)` ([bp](bp:778)). A hand-written same-issue takeover that merely names an unseen claim supersedes it. The real owner's close is then marked stale and the issue stays in progress. An honest online takeover normally sees the fetched claim, so this is classified as hostile/corrupt input, not a demonstrated ordinary protocol race.

## Ranked finding: compatibility identity

### K01 — Medium: valid comment-ID collisions renumber an existing export

The hash-derived range resolves ordinary compatibility and the exact small-legacy-ID R13 regression. Collision resolution, however, depends on the set and iteration order at export time ([bp](bp:1286)). The deterministic fixture finds two valid event IDs with the same initial numeric bucket:

- Exporting the first comment alone gives one integer; after the second machine arrives, the first comment's integer changes.
- Importing a later legacy comment whose integer equals an existing hash-derived integer also increments and renumbers the existing comment.

Full event projections converge, but the externally exported integer identity is not stable across later valid data, contrary to the current README wording. This is not merely a birthday-probability argument; the suite finds and uses a concrete pair deterministically.

Ordinary consumer compatibility was otherwise strong: 24 real trackers (2,663 issues, 886 comments) imported and canonically round-tripped through `bp`; `br` 0.5.7 loaded 22/24 originals and the same 22/24 `bp` exports, with the same pre-existing `project-a-5gd.2` and `runledger-wtb` semantic failures; ready/blocked matched all 22 loadable trackers; and `bv` 0.25.0 returned valid JSON for triage, plan, and insights on all 72 calls. A generated high-ID tracker survived `bp → br → br mutation/flush → bp` and six `bv` modes across 32 focused subprocess calls. This healthy non-collision path does not negate K01. See [compatibility3_findings.md](/tmp/bp-review3-vo_4_qph/compatibility3_findings.md).

## Documentation observation

### D01 — Low, pre-existing: `find_cycles` does not enumerate every elementary cycle

The iterative implementation fixes R11's recursion overflow. Independent valid 5,001-node DAG and 5,001-node cycle checks complete. But for `A→B`, `A→C`, `B→C`, `C→A`, `find_cycles()` reports `A-B-C-A` and misses `A-C-A`, despite its docstring promising every elementary cycle ([bp](bp:1165)). The recursive predecessor behaved the same way, so this is not a regression in the R11 fix. Either the algorithm or the docstring/CLI contract should be narrowed.

## Review of adapted tests

The passing adapted suite is useful but is not sufficient evidence that every original safety family is closed.

- The R01 delayed-receive-pack rewrite legitimately tests the new pending/fence design and preserves the original no-fork/no-loss invariant. The plain lost-ack author test uses idempotent `claim`, while crash-followed-by-`sync` does not rerun a non-idempotent command. Neither catches release/bundled rebuild.
- The R03 tests preserve the final ownership and bundled-edit invariants, though names/messages still mention the removed void design. `original_ids` at [test_reaudit.py](test_reaudit.py:393) is unused; the new rejected-fence test separately verifies exact pending-ID retention.
- Replacing the old rotated-journal unlink case with journal byte-identity and pending bundled files is appropriate for the detached representation. One assertion at [test_reaudit.py](test_reaudit.py:660) compares the claim thread to nonexistent top-level `info.thread`; `info` nests it under `actor`, so that line cannot distinguish the accepted owner from a rejected one. The adjacent dedicated reader test still checks the exact failed event ID. No shipped test pauses or kills confirmation of an accepted multi-file attempt.
- The R10 fault hook correctly moved from destination `os.open` to the atomic `os.link` install boundary, and the new assertions are stronger: both workspaces must receive one ID, and a killed initializer leaves no visible destination.
- The all-register fixture now supplies integers for integer registers instead of invalid strings. This restores the intended `None`-versus-valid-value conflict invariant.
- The permutation test now delivers detached ownership files as detached files, preserving and strengthening its original event-set invariant.
- The R13 fixture imports legacy ID 41. With new IDs starting at 1,000,000 it cannot exercise collision handling, so it proves only that particular original scenario. The deterministic collision tests expose the broader stability failure.
- R02, R05–R09, and R11's named regression methods are otherwise unchanged from the previous report; their exact cases pass.

## Stress, feature, identity, and privacy checks

The strengthened current model ran six concurrent workers through ten partition/rejoin waves and 3,000 commands (seed 20261008). It ended with 183 issues, 1,623 events, 91 distinct accepted claim IDs, and maximum generation 12. Expected domain refusals were 114 `ALREADY_CLAIMED`, 80 `NOT_OWNER`, and 3 `CYCLE`; there were no retry-exhaustion or reachability failures. The wrapper added 186 checks that `pending_ownership` was empty after `info`/`sync`. Artifact: [concurrent-review3.json](/tmp/bp-review4-BXQkIo/concurrent-review3.json).

Location suppression outside a checkout and with `"where": false` also passed.

Identity detection tests for explicit overrides, environment detection, nearest mocked harness in a nested process tree, human-shell fallback, and unavailable `ps` all passed. No paid Codex or Claude process was launched. The 48-process identity initialization check is described under R10.

## Scratch candidate and proposed diff

The only code candidate tested was the supplied narrow receipt patch, retained as [protocol-receipt-fix.diff](/tmp/bp-review3-vo_4_qph/protocol-receipt-fix.diff) and [bp.protocol-release-fix](/tmp/bp-review3-vo_4_qph/bp.protocol-release-fix). It remembers the just-pushed event list in the current process and returns the saved result when the next fetch confirms all files. Four targeted protocol tests passed on that scratch copy.

It is **not a complete fix** and was not applied to the reviewed `bp`: the receipt is only in memory, so a crash followed by a new process still reports `NOT_OWNER`; it also does not make multi-file local confirmation atomic. No untested replay or collision patch is proposed.

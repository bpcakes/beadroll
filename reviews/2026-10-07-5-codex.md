# beadroll: fifth independent review

## Reviewed version and assessment

I reviewed commit `06f8b9fa67a93117838ea00217f45990a377037d` on macOS 26.6.2 arm64,
Python 3.14.7 and Git 2.55.0. The checkout was clean at the start; the final working-tree delta is
only this report and the new `tests/test_review5.py`. I did not modify `bead`, existing tests,
documentation, the findings ledger, or earlier reports.

The existing suite gives substantial evidence for causal convergence, journal repair, conditional
claim publication, import/export compatibility on the retained real trackers, and the fixes from
reviews 1–4. The full shipped stress suite passed. This review found thirteen residual failures:
six high-impact failures involving terminal injection, credential disclosure, claim fencing,
false import success, receipt identity, and failure after a committed mutation; and seven medium
robustness, automation, or query failures. Two positive controls passed.

The most important distinction is between beadroll's domain protocol and its process boundary.
The randomized causal/claim models remain strong, but several byte-stream and validation paths can
misreport what happened, disclose data, or execute terminal controls before an operator can use
that protocol safely in automation.

## Findings, ranked by impact

### E01 — High / P0: human output executes untrusted terminal controls and permits forged lines

Location: `line` and the human renderers, especially `bead:1410`, `bead:1918`, `bead:2137–2166`,
`bead:2229`, `bead:2313`, and `bead:2552`.

Reproduction: `Review5CLI.test_e01_human_output_escapes_terminal_controls` creates a title containing
OSC 52, BEL, and an embedded newline, then captures `create` and `list`. Both stdout streams contain
the literal `ESC ] 52 ... BEL` bytes and a new physical `FORGED: success` line. The same boundary is
present in comments, descriptions, labels, actor names, aliases, errors, and several other human
renderers.

Expected: preserve the original value in the journal and JSON, but render ESC, C0/C1 controls,
carriage return, backspace, field-breaking tabs/newlines, and security-relevant bidi controls as
visible literals in human output. Machine JSON is already a useful positive control: V01 proves that
it escapes the bytes and round-trips the exact value.

Impact: a peer journal, imported tracker, or ordinary argument can clear or rewrite the display,
set the terminal title, create misleading status lines, or trigger terminal features such as
clipboard writes. This is a terminal injection boundary, not a cosmetic formatting issue.

Remedy: centralize human-field escaping and apply it before every human renderer. Keep raw export
and JSON serialization separate; do not strip or mutate stored data.

### E02 — High / P0: credential-bearing remote URLs are disclosed and stored in permissive files

Location: `Workspace.save_meta`/`remote` and `write_atomic` (`bead:106–128`, `bead:161–168`), plus
`cmd_info` and `cmd_sync` (`bead:2342–2357`, `bead:2376–2387`).

Reproduction: `Review5CLI.test_e02_remote_credentials_are_not_disclosed_or_world_readable` runs
`init --remote https://alice:supersecret@example.invalid/private.git`. `info --json` returns the
password verbatim, `meta.json` stores it verbatim, and the file mode under the normal `022` umask is
`0644`. Direct inspection also found store directories at `0755` and journal segments at `0644`.
Fetch errors and successful sync text interpolate the same URL.

Expected: reject credential-bearing URLs in tracked config/arguments in favor of Git credential
facilities, or separate secret material from the display/persisted endpoint. Redact user-info and
sensitive query components from diagnostics. Create private state directories/files with `0700` /
`0600` (and migrate or warn on existing permissive state).

Impact: credentials can enter logs, JSON automation output, support transcripts, and locally
readable state. `init --tracked --remote` can additionally write the URL into a file the user is
told to commit.

### E03 — High: a takeover does not fence the prior owner's concurrent offline delete

Location: the takeover supersession pre-pass (`bead:849–861`), `apply_event` close/release/delete
handling (`bead:960–1010`), and the generic transition builder (`bead:2102–2127`).

Reproduction: `Review5CLI.test_e03_takeover_fences_an_owners_concurrent_offline_delete` performs:

1. A claims an issue online.
2. A deletes it with `--offline`.
3. B, which has not seen the delete, takes over A's confirmed claim online.
4. Both machines sync.

The merged issue has B's live generation-2 claim plus a `status` conflict between `tombstone` and
`in_progress`. In a follow-up probe B's ordinary `release` returned success and wrote `open`,
settling away the tombstone. `close` avoids this class by naming the claim it ends, but owner
`delete` does not include that identity and has no stale-claim check.

Expected: an owner's delete should name its claim and be stale if a coordinated takeover superseded
that claim, just as owner close/release are. A forced non-owner delete can remain an explicit,
separate path. At minimum, a terminal status must not coexist with a live confirmed claim that can
later release it to `open` without an explicit reopen decision.

Impact: the takeover does not fully fence the old owner, and a deletion can become a hidden conflict
then disappear through routine release semantics.

### E04 — High / P1: import reports success for records that replay deliberately discards

Location: `import_records` and `cmd_import` (`bead:1845–1877`) versus deferred event validation in
`replay` (`bead:845–848`).

Reproduction: `Review5CLI.test_e04_invalid_import_fails_instead_of_counting_an_inert_event` imports a
record whose status is `not-a-status`. The command exits 0 with `{"imported":1}`, appends the create
event, and reports no warning. `show ex-invalid` then returns `ISSUE_NOT_FOUND`; only `info.integrity`
reveals that replay rejected the event.

Expected: validate and normalize every source record and generated event before appending anything.
Reject the import atomically with a structured `VALIDATION` error, or implement an explicit partial
result that counts accepted/rejected records and exits nonzero when the requested import is not
complete.

Impact: migration automation can discard its source after a success result even though beadroll has
no corresponding issue. Mixed files can silently produce partial imports while returning the full
input count.

### E13 — High: lost-ack receipts omit resolved file/stdin content from command identity

Location: `field_args` resolves file/stdin data before coordination (`bead:1236–1265`), but
`command_signature` records only argparse values (`bead:1667–1672`) and `settle_commands` treats an
equal argv/actor receipt as completed (`bead:1675–1694`).

Reproduction: `Review5CLI.test_e13_receipt_identity_includes_resolved_file_content` runs a claiming
update with `--description-file description.txt` containing `first body` and injects
`BEAD_TEST_CRASH_AFTER_PUSH=1` after the real local remote accepts it. It then changes the same file
to `second body` and reruns the same argv. The retry exits 0, returns the accepted first result, and
silently leaves `first body`; no second set event is emitted.

Expected: the command receipt must cover the normalized semantic request, including resolved file
or stdin bytes (preferably a canonical digest plus the fields used to build the attempt). Changed
content is a new command after the accepted attempt is settled; unchanged content remains an
idempotent retry.

Impact: the per-command recovery added for Q02 can silently discard a legitimate follow-up edit.
The same ambiguity affects `--description-file -`, where argv is constant but stdin is command data.

### E12 — High / P1: reduced output encoding reports failure after `create` already committed

Location: unconditional Unicode icons (`bead:36`, `bead:1410`, `bead:1919`) and final rendering after
the write transaction (`bead:2538–2553`).

Reproduction: `Review5CLI.test_e12_ascii_locale_cannot_turn_a_committed_create_into_failure` runs
human `create` with `LC_ALL=C`, `LANG=C`, `PYTHONUTF8=0`, and `PYTHONCOERCECLOCALE=0`. The journal
append succeeds. Printing `✓ Created ...` then raises `UnicodeEncodeError`, emits a traceback, and
exits 1. A normal JSON `list` immediately proves the issue exists.

Expected: choose an encoding-safe plain/ASCII representation or establish a deliberate UTF-8 output
contract before mutation. Rendering/delivery failures after commit need an explicit receipt policy
that does not invite a blind retry of a successful non-idempotent command.

Impact: a caller sees failure after success and may retry, creating duplicate issues. Non-ASCII user
data in `--json` has the same risk because `ensure_ascii=False` reaches the locale stream after the
mutation.

### E05 — Medium / P1: `create --silent --json` emits a raw identifier, not JSON

Location: the direct print in `cmd_create` (`bead:1917–1920`) runs before the global serializer
(`bead:2547–2552`).

Reproduction: `Review5CLI.test_e05_silent_create_still_honors_json_mode`. Both
`bead create one --silent --json` and `bead --json create one --silent` exit 0 with `ex-...\n` on
stdout; a strict JSON parser rejects byte 1.

Expected: `--json` wins for the representation. Keep raw-id `--silent` behavior only in text mode,
or reject the combination before creating the issue.

### E06 — Medium / P1: accepted non-finite numbers produce invalid Beads JSONL

Location: permissive `json.loads` in import/journal/config paths and default `allow_nan=True` in
export (`bead:1845`, `bead:1882`, and the other JSON boundaries).

Reproduction: `Review5CLI.test_e06_export_never_emits_nonfinite_json_numbers` imports an otherwise
valid record with unknown field `"score":NaN`. Python accepts it, import exits 0, and export emits
the literal token `NaN`. A parser that rejects non-RFC-8259 constants rejects the successful export.

Expected: reject `NaN`, `Infinity`, and `-Infinity` while parsing, and serialize contractual JSON
with `allow_nan=False` as a defense in depth.

### E07 — Medium / P1: an early downstream close exits 120 and prints Python flush noise

Location: stdout writes in `cmd_export`/`cmd_create` and the final `print` calls (`bead:1882–1887`,
`bead:1918`, `bead:2547–2552`) have no delivery/`BrokenPipeError` policy.

Reproduction: `Review5CLI.test_e07_closed_downstream_pipe_has_defined_quiet_exit` closes the stdout
reader before `show` writes. The process exits 120 and stderr contains
`Exception ignored while flushing sys.stdout: BrokenPipeError`. `export` behaves identically.

Expected: define early consumer closure semantics (quiet 0 for read-only producers or signal-style
141 are both conventional choices), flush inside the controlled exit path, and never print an
irrelevant Python diagnostic. Mutating commands need the same explicit post-commit receipt policy
called out in E12.

### E08 — Medium / P2: values accepted as nullable crash human and export renderers

Location: payload validation accepts nullable imported comment timestamps and dependency types
(`bead:482–490`), while human renderers slice timestamps (`bead:2161`, `bead:2313`) and export sorts
raw dependency types (`bead:1459`).

Reproduction: `Review5CLI.test_e08_nullable_import_values_do_not_crash_render_or_export` demonstrates
three paths:

- an imported comment with `created_at: null` makes human `show` raise `TypeError`;
- the same record makes human `comments` raise `TypeError`;
- two dangling dependencies on one target, with types `null` and `"blocks"`, import successfully but
  make export compare `None` to `str` and raise `TypeError`.

Expected: normalize nullable values at import/replay (for example, normalize a null dependency type
to `blocks`) and make human formatting explicitly represent missing timestamps. A value accepted by
validation must be safe in every advertised read/export path.

### E09 — Medium / P2: valid JSON with wrong config types escapes as tracebacks

Location: `find_workspace`, `Workspace.ref`, and `Workspace.remote` (`bead:110–158`) assume the
decoded config and selected keys are strings.

Reproduction: `Review5CLI.test_e09_invalid_config_types_return_structured_config_errors` tries
`.beadroll.json` values `[]`, `{"workspace":"safe","ref":42}`, and
`{"workspace":"safe","remote":{"url":"x"}}`. `info --json` exits 1 with unstructured
`AttributeError`/`TypeError` tracebacks in all three cases.

Expected: require a JSON object, validate known key types once, reject unknown/incompatible values
as `BpError("CONFIG", ...)`, and preserve the JSON error envelope.

### E10 — Medium: `extra` can forge canonical identity and state in exported records

Location: create payload validation accepts any object as `extra` (`bead:480`), replay stores it
unchanged (`bead:906`), and export applies it after canonical fields (`bead:1444–1447`).

Reproduction: `Review5Replay.test_e10_extra_cannot_override_canonical_export_fields` supplies a
validly enveloped create event whose `extra` contains `id: ex-spoof`, `status: open`, and
`comments: "forged"`. Replay reports no integrity problem and internally shows `ex-real` as
tombstoned. Export instead reports `ex-spoof` as open with a non-array comments value.

Expected: reserve all canonical Beads keys. Either reject collisions during payload validation or
merge extras first and canonical fields last while removing reserved collection keys when empty.

Impact: a malformed or hostile peer journal can make downstream `br`/`bv` consumers see a different
issue identity and state from beadroll's own projection.

### E11 — Medium / P2: `--parent` filters only the first of several direct parents

Location: `parent_of` returns the first parent (`bead:1344–1347`) and `select` uses only that value
(`bead:2195–2198`).

Reproduction: `Review5CLI.test_e11_parent_filter_matches_every_direct_parent` creates two parents,
adds both as `parent-child` dependencies through the public `dep add` command, and filters by each.
The child appears for the first parent and disappears for the second even though `show.dependencies`
lists both. Concurrent parent moves and imports can produce the same valid state.

Expected: test membership across `parents_of`, or explicitly reject/resolve multiple parents at the
write boundary. The machine detail schema should avoid presenting a lossy singular `parent` as the
complete relationship.

## Performance and scale

The retained `scale_replay.py` builds a valid single-machine history in one process and replays it
in a fresh process for each size. The first run overlapped the shipped stress suite, so its latency
figures are not used as final evidence. Final isolated results:

```text
{"events": 10000, "build_seconds": 0.034, "replay_seconds": 0.69,
 "max_rss_mib": 44.6, "integrity": 0, "pending": 0}
{"events": 50000, "build_seconds": 0.197, "replay_seconds": 3.43,
 "max_rss_mib": 124.8, "integrity": 0, "pending": 0}
{"events": 200000, "build_seconds": 0.971, "replay_seconds": 13.821,
 "max_rss_mib": 412.0, "integrity": 0, "pending": 0}
```

The process-level `scale_import.py` control imported 1,000 / 5,000 / 10,000 ordinary issues in
0.205 / 1.004 / 3.289 seconds; a fresh `list --all --limit 1 --json` over those stores took
0.180 / 0.783 / 2.515 seconds, respectively. All six commands exited 0.

These are synthetic in-memory histories, not sync throughput measurements. Peak RSS is process
maximum resident size. The 200,000-event result should be compared with the README's approximate
2-second replay statement only with the recorded Python/OS/hardware context; it is a documentation
and planning observation, not a request to reverse the accepted no-projection POC decision.

Cold `./bead --help` was 0.06 seconds on this machine.

## Proposed repair order

1. Fix E01 and E02 before treating human output or diagnostics as safe around imported/peer data.
2. Fix E03, E04, E12, and E13 before relying on command status for unattended ownership or migration.
3. Make the JSON/output contract strict (E05–E07), then normalize every accepted nullable value
   and config key (E08–E09).
4. Protect canonical export keys (E10) and make the parent query complete (E11).

Each repair should keep its E test as a process-level regression. E03 also deserves an in-process
two-order replay control so UUID ordering cannot change the stale-delete result.

- A physically full filesystem, every possible kill boundary, arbitrary remote byte rewrite beyond

- Remote object growth over 1,000 changing sync commits, with and without `git gc`.
- Exhaustive argv/option permutations and every possible malformed JSON schema value.

# Every test of the Python suite, its port class and, where it is not ported under its own name,
# what replaces it: the inventory `cargo xtask inventory` reports (docs/RUST-PORT.md §4.2). Seeded
# from the catalogues in docs/rust-port/; rows that cover several tests there ("t1", "t2") are split
# per method, in file order. One test per line:
#
#   CLASS  TEST-ID  [=> RUST-TEST[, RUST-TEST...]]  [# note]
#
# CLASS is the catalogue's: A (black-box), A† (black-box on the two crash hooks), B (pure logic,
# a Rust unit test), C (an injection seam: failpoints or a library API), C-env (a hook the
# environment triggers), C-api (an in-crate API), D (Python-specific; the note says what replaces
# it). A Python test counts as ported when a Rust test's path holds its class and method segments
# in that order: test_x.SomeClass.test_does_y is ported by x::some_class::does_y, or by a path such
# as x::group::some_class::does_y. A test listed with `=>` is ported by those Rust tests instead.
